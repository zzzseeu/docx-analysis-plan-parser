# Bioinformatics Department Execution and Analysis Standard

本文档依据以下内部规范整理，用作 `bioinformatics-diagnosis-workflow` skill 的执行准则：

- `templates/生信分析部门执行规范（研究员团队）20260629(1).pdf`
- `templates/数据分析部门项目分析标准v5.0.pdf`

本规范只保留与 skill 自动化、分析执行、报告生成、审核交付直接相关的要求；薪酬、税务、外部网盘教程链接、个人账号和非必要服务器细节不作为 skill 行为规则。

## 1. 总体原则

1. 项目进入分析后即采用项目责任制：分析人员或代理工作流需要保证结果专业准确、项目周期可控、代码和结果可复现。
2. 方案文档、客户确认和项目沟通记录是需求来源。不得虚构基因、数据集、样本量、阈值、结论或不存在的结果。
3. 默认采用阶段化执行。每个阶段完成后写出 Markdown 和 manifest.csv，并暂停等待用户确认。
4. 任何调整分析路线、阈值、数据集、验证方式或结论口径的动作，都必须写入 `workflow/PROJECT_MEMORY.md` 和对应阶段的 manifest `notes`。
5. 分析中遇到数据、方案、统计或软件问题时，先记录已尝试方法、输入数据、报错或失败原因，再给出备选方案和需用户确认的问题。
6. 所有可自动化分析都应输出可复现脚本；长时间、大规模、GUI、在线数据库或 Cytoscape-heavy 步骤默认进入人工交接。
7. 结果用于报告前必须通过交付前质控：路径存在、文件格式正确、图表可读、样本分组和方向正确、结论来自真实结果。

## 3. Project Directory and Script Rules

### 3.1 Project Root

1. 一个项目建立一个项目目录，推荐形如 `01_project1003` 或 `01_project_007`，序号使用双位数字。
2. 每个项目必须有独立 R 工作空间；git 仓库可选。
3. 公司服务器场景下，不得在家目录执行分析；应在个人工作目录下创建项目目录。Codex 本地执行时，遵循当前 workspace 根目录，不把临时文件混入交付目录。
4. 一个分析点对应一个结果目录，目录格式为 `双位数字_英文缩写或英文全拼`，例如 `00_rawdata`、`01_DEG`。禁止中文、空格和含义不清的目录名。
5. 交付目录中不要保留临时 smoke-test 数据、临时日志、一次性 pass/fail 文件或无关缓存。

### 3.2 Script Rules

1. 一个分析点对应一个脚本；脚本必须能一键从头执行并复现交付结果。
2. Skill 生成的 R 脚本使用 `r.{{step_num}}_{{step_name}}.R`，匹配结果目录 `{{step_num}}_{{step_name}}`。
3. R 脚本必须从项目目录启动，在分析点目录内写结果：

```r
rm(list = ls()); gc()
pwd <- "{{PROJECT_DIR}}"
res_folder <- "{{step_num}}_{{step_name}}"

setwd(pwd)

if (!dir.exists(paths = file.path(res_folder))) {
  dir.create(res_folder)
}

setwd(res_folder)
```

4. 读取上游文件时优先使用相对路径，并从项目目录或分析点目录明确定位。
5. 少量辅助函数可以直接写在脚本中；不要依赖未交付的外部脚本或自封装 R 包。
6. 保存路径不得隐藏在函数内部，便于审核人员定位输出。
7. 输出文件名需与内容相关，并用编号排序，例如 `01.DEG_all_res.csv`、`02.DEG_sig_res.csv`。
8. 文本表格统一保存为 CSV；避免将核心结果只保存为 `.txt`、`.xlsx` 或不可复现的二进制文件。
9. 图表至少保留 PNG；需要审核或二次编辑时可同时保留 PDF。Word 报告只插入 PNG。
10. 脚本应记录关键参数、阈值、随机种子、软件包和数据库版本。

## 4. Data and Preprocessing Standards

1. GEO 高通量测序数据不建议直接使用 NCBI 官网定量后的数据；若使用，必须核对样本信息。
2. 注释文件已经给出 gene symbol 时，禁止再用 `bitr` 或其他方法自行转换 gene symbol，除非方案或数据缺失要求。
3. 需要进行 gene symbol 转换时，不允许用探针 ID 做差异分析；注释版本必须正确，例如 TCGA 数据常用 GENCODE v36。
4. 预后项目中患者样本不得重复，例如同一 TCGA 患者的不同 aliquot 不能作为独立样本重复进入模型。
5. 训练集、验证集和单细胞数据集应尽量保持疾病定义、发病部位、病情严重程度、取样人群和组织类型一致。
6. 方向基因必须核对名称和别名，警惕两个基因粘连、旧名、新名或物种不匹配。
7. 模型训练前禁止为了匹配验证集而先对训练集和验证集取交集基因；验证集缺失基因时，应先查找基因别名，并记录缺失处理。
8. FPKM、TPM 或标准化矩阵需要检查是否已标准化和是否 log2 处理。一般标准化值范围不应异常偏大，必要时用 `range()` 辅助判断。
9. `log2(count + 1)` 不用于任何分析；`log2(FPKM + 1)` 或 `log2(TPM + 1)` 可用于除差异分析之外的其他分析。
10. 高通量测序数据若同时有 raw count 和 FPKM/TPM：差异分析使用 raw count，其他分析统一使用 FPKM 或 TPM，不得混用。
11. 高通量测序数据若没有 count 数据，不能作为训练集进行差异分析。

## 5. Differential Expression

1. Count 数据使用 DESeq2；芯片或标准化表达矩阵使用 limma。
2. 统计学差异优先使用 adjusted p value 或 padj。
3. 最低筛选标准为 `pvalue < 0.05` 且 `abs(logFC) > 0.5`；仅用 pvalue、仅用 padj 或进一步降低 logFC 均属于特殊阈值，需要记录参考文献和客户或主管确认。
4. 差异基因少于 100 个时，需要反馈确认可行性；过多导致 PPI 等下游无法执行时，可有依据地提高 logFC 阈值。
5. 差异分析前需要生成 PCA 图和箱线图，观察批次效应、离群样本和组内一致性；热图也需检查分组表现。
6. 禁止先合并数据集再去批次做差异分析，除非方案明确允许；需要合并时必须同平台，并提前沟通。
7. 分组文件和表达矩阵样本顺序必须一致。
8. DESeq2 需检查 `results()` 中对比方向；limma 需检查 `makeContrasts()` 中 `+1` 和 `-1` 对应的 case/control。
9. 使用特殊阈值或调整分析路线时，报告必须说明原因和依据。

## 6. WGCNA and hdWGCNA

### 6.1 WGCNA

1. 总样本量不低于 15，不区分组别。
2. 输入为标准化表达矩阵；高通量数据使用 TPM 或 FPKM，并与其他分析点保持一致。
3. 表达矩阵应使用所有合格基因，不能只用差异基因矩阵。
4. 低表达或不表达基因需过滤。
5. 软阈值需使 scale-free `R^2 >= 0.8`，推荐 0.85 或 0.9，同时平均连接度一般低于 200；通常选择刚满足条件的第一个阈值。
6. 候选模块最低要求：模块与性状 `abs(r) > 0.3` 且 `pvalue < 0.05`；优先选择绝对相关性最高模块。灰色模块不纳入候选。
7. 模块-性状相关默认 Pearson；若分布不支持 Pearson，应说明并考虑 Spearman。
8. MM/GS 常用阈值为 `GS > 0.2`、`MM > 0.8`；其他阈值需要文献支持。
9. 模块数量需适中，可通过聚类参数调整。
10. 报告需写清使用全部样本还是疾病样本。

### 6.2 hdWGCNA

1. 性状不宜直接使用疾病状态，可使用细胞类型、方向基因集评分或其他连续表型筛选模块。
2. 关键细胞可基于关键基因 AUCell 评分、疾病相关细胞或方案指定细胞确定。
3. 细胞数不足时应合并亚群、调整 metacell 策略或列入风险。

## 7. Gene Set Scoring

1. 需说明评分是在全部样本还是疾病样本中进行。
2. 第三方基因集评分方法优先使用 ssGSEA。
3. 方向基因用于评分时，基因数应大于 10 且小于 200；ssGSEA 最低不低于 10 个基因，30 个以上更稳。
4. 诊断项目关注评分在疾病组和正常组间是否显著差异。
5. 预后项目关注评分在肿瘤或疾病样本中是否有生存差异。

## 8. Network Analysis

### 8.1 PPI

1. PPI 输入基因最低 10 个，最多不超过 2000 个。
2. 不推荐仅凭 PPI 网络主观筛选关键基因；应结合 Cytoscape CytoHubba 多算法，并保存每种算法图片和完整结果表。
3. 选择 TopN 基因时不得存在边界并列，例如第 10 和第 11 名分数相同。可更换算法、调整 TopN 或使用 degree 中位数等客观阈值。
4. 若 PPI 用于展示互作关系，可保留孤立点；若用于筛选核心基因，应去掉孤立点。
5. STRING 置信度阈值必须交代清楚。常用 0.4，可按结果和文献在合理范围调整。
6. Cytoscape 美化后需保存 `.cys` 项目文件。
7. 基因过多不便展示时，可按 degree 等指标选择 Top30 绘图，并保留全量表格。

### 8.2 GeneMANIA

1. 输入基因不宜过多，建议 10 个以下。
2. 图上应区分输入基因和 GeneMANIA 补充基因。
3. 需展示或描述疾病潜在相关生物学过程。

### 8.3 ceRNA and Regulatory Networks

1. ceRNA、TF/miRNA-mRNA、TF-miRNA-mRNA 等多数据库预测取交集时，必须取关系对交集，不能只取靶点交集。
2. 正文需描述节点数、关系对数量、筛选数据库和阈值。
3. 物种不匹配时需先做同源基因转换并标注风险。

## 9. Diagnostic ROC, Expression Validation, and Machine Learning

### 9.1 Single-Gene ROC

1. 诊断 ROC 要求 AUC > 0.7 且不能等于 1。
2. 样本量建议至少 8 vs 8；低于该数量需要申请或标记风险。
3. 训练集中单基因 ROC 必须通过 AUC 阈值；验证集不通过时可记录为验证失败，不应强行解释。
4. 基因过多时可提高 AUC 阈值至 0.8 或 0.9 进一步筛选。
5. ROC 图线条颜色需区分明显，标签字体不可过小。

### 9.2 Single-Gene Expression Validation

1. 表达趋势需一致且统计学检验显著。
2. 通过验证的基因至少 2 个。
3. 诊断类型关键基因最多 5 个，且必须有单基因表达量外部验证；没有外部验证需申请。
4. 预后类型关键基因最多 8 个。
5. 训练集优先使用统计学检验结果；不显著时可替换为差异分析统计结果并记录原因。
6. count 与 FPKM 趋势不一致时，优先对 count 做 VST 标准化后进行秩和检验；若采用 VST，则其他分析点数据也应统一。
7. 诊断验证时，用于表达验证的基因总数最多 15 个，通过比例不低于 20%，例如 15 个至少通过 3 个。
8. 验证集最多缺失 1 个基因；超过 1 个需调整方案或更换验证集。缺失基因需先尝试查找别名。

### 9.3 Diagnostic Model ROC

1. 模型 ROC 需 AUC > 0.7，且模型 AUC 应大于单基因 AUC；否则考虑不展示单基因 ROC。
2. 模型 AUC 和单基因 AUC 不允许等于 1；若出现可替换为混淆矩阵、PR 曲线或 C-index，并说明原因。
3. 样本量建议至少 8 vs 8。
4. 图中需标注最佳截断值和 95% 置信区间。

### 9.4 Machine Learning

1. 样本量建议至少 8 vs 8；低于该数量需要申请或标记风险。
2. 交叉验证折数按样本量确定：十几个样本通常 3-fold，其他可用 5-fold 或 10-fold；每折最低不少于 3 个样本。同一项目不同机器学习折数应一致。
3. 分组因子水平设定为正常对照 0、疾病 1。
4. 自限性方法与自限性方法取交集，非自限性方法与非自限性方法取交集；若取不到，再说明原因后交叉取交集。
5. SVM-RFE、LASSO、XGBoost、Boruta 可直接筛选基因；RF、GBDT 输出重要度；LR、简单 SVM 和 ANN 通常为分类模型，不直接输出可解释特征。
6. SVM-RFE 和 RF 等模型错误率不得为 0，精确度不得为 1。
7. XGBoost 特征列名只能使用字母，不能含数字开头或不合法字符。
8. 若进入机器学习的基因数和输出基因数相同，说明算法未起筛选作用，应更换方法或调整策略。
9. 诊断机器学习模型准确度应高于 80%，最低误差不得超过 20%。
10. 113 机器学习中，训练集 AUC 为 1 但验证集 AUC 不为 1 时，可视为有效模型；训练集和验证集 AUC 均需大于 0.7。
11. 方案指定 LASSO 时必须先尝试 LASSO 并保留结果；若替换为弹性网络，需申请并遍历 alpha 选择最优结果。

## 10. Prognostic Analysis

1. 区分预后风险模型和独立预后模型：风险模型由基因构建；独立预后模型由 riskScore 和临床特征构建。
2. 单因素 Cox 前需对每个因子做 PH 假定检验，要求 `PH.p > 0.05`。
3. 单因素 Cox 阈值首选 `p < 0.05`；可按套餐或方案申请放宽至 `p < 0.2`。当使用 `p < 0.2` 时，置信区间需相应调整并记录。
4. 可用建模方法包括 LASSO-Cox、多因素 Cox、逐步回归、CoxBoost、randomForestSRC。
5. 常见风险模型路径包括：单因素 + LASSO、单因素 + 多因素、单因素 + RSF、单因素 + LASSO + 多因素、单因素 + LASSO + RSF。
6. 多因素模型中的基因 p 值可大于 0.05，但所有变量 PH 检验必须大于 0.05。
7. 独立预后模型必须包含 riskScore 和至少 1 个临床特征；若只有 riskScore，则不构建列线图。
8. 列线图需使用独立预后因素构建；单因素和多因素阈值应小于 0.05。
9. 列线图 AUC 需大于 0.6，并至少另有一个评估指标通过，例如校准曲线 `p > 0.05` 或 DCA 显示优于单变量。
10. 预后 ROC 中训练集和验证集同一年份 AUC 均需大于 0.6；非常规年份需参考文献。
11. 训练集和验证集的生存类型（OS、PFS、DFS 等）和时间单位必须统一。
12. 101 或 113 预后模型中训练集和验证集 AUC 必须大于 0.6。
13. 需要确认绘制 ROC 年份是否有足够生存样本；若某年份无满足样本，不允许绘制该年份 ROC。
14. 宫颈癌、甲状腺癌、子宫内膜癌预后项目可申请不用外部验证，采用 7:3 划分加整体验证；其他癌症通常仍需外部验证。

## 11. Enrichment and Pathway Analysis

### 11.1 GSEA

1. 常见类型包括单基因 GSEA 和高低风险组 GSEA。
2. 使用 clusterProfiler 时需设置随机种子，避免随机性影响复现。
3. 背景基因集优先使用 KEGG。
4. 单基因 GSEA 排序可使用高低表达组差异结果 logFC，或单基因与全部基因的相关性。
5. 单基因 GSEA 后需进一步对关键基因共有通路做 GSVA。
6. 阈值为 `abs(NES) > 1` 且 `p < 0.05` 或 `adjust.P < 0.05`。

### 11.2 GSVA

1. 差异分析使用 limma。
2. 常用阈值为 `abs(t) > 1` 且 `p < 0.05` 或 `adjust.P < 0.05`；最低可放宽至 `abs(t) > 0`，需记录理由。

### 11.3 GO/KEGG

1. 优先采用校正后 P 值。
2. 用于富集的基因数不得少于 10 个；不足 10 个时转为单基因 GSEA 或记录无法开展。

## 12. Molecular Docking and Drug Analysis

1. 分子对接需写清选择化合物和靶蛋白的理由。
2. 需说明结合能；可参考最大值 `-1.2 kcal/mol` 或 `-5 kJ/mol`，具体按文献和方案执行。
3. 图形建议包含一张整体图和一张局部放大图。
4. 需说明蛋白结构来源或 PDB ID；若蛋白结构仅为螺旋链，可改用棍棒形式展示。
5. 药物敏感性预测中药物数量较多时，优先展示与 riskScore 高相关药物的箱线图。
6. GraphBAN 分析中 pred 最低阈值为 0.5，需三个模型同时满足。可使用最优 3 个模型取交集，也可用 2 个或 1 个模型，但需说明理由。
7. GraphBAN 构建蛋白-成分关系对时，应按分析目的区分全连接排列组合和固定数据库预测关系对。
8. 类药性和毒理性阈值若不使用方案阈值，需提供文献；若毒理性指标均不通过，可删除毒理性评估分析点并记录。
9. 最终调控网络至少保留 2 个关键基因，活性成分尽量不唯一，并评估成分是否有实际价值。

## 13. Immune, Clustering, MR, and Multi-Omics

### 13.1 Immune Analysis

1. 非肿瘤项目也可以做免疫浸润。
2. 常用算法包括 CIBERSORT、ssGSEA、xCell、TIMER 等；小鼠可用 CIBERSORT 或 ssGSEA。
3. 可使用 `immunedeconv` 等 R 包。
4. 细胞名称需要使用更新后的版本，并保证报告中名称一致。
5. 免疫治疗分析常见 TIDE 和 IPS。

### 13.2 Clustering

1. 一致性聚类最小样本数应为 30。
2. 一致性聚类需展示 CDF 曲线和热图，选择最快到达平台期的 K。
3. NMF 需展示热图和折线图，通常选择斜率下降最快的前一个点。
4. 预后项目要求类间生存差异；非预后项目要求类间具有临床或功能差异。

### 13.3 Correlation and MR

1. 各类相关性系数最低阈值为 0.3。
2. 相关性方法需区分 Pearson 和 Spearman；除非确定分布类型，否则不建议使用 Pearson。
3. MR 的 OR 值和基因表达上下调不要求一致，但可按上下调筛选。
4. 预后类型中，若基因为暴露因素，MR 的 OR 值方向应与单因素 Cox 的 HR 方向一致。
5. MR 留一法检验不能跨线。
6. OR、HR 或 CI 特别大时可判定为异常并排查低表达、离群样本或模型问题。

### 13.4 Multi-Omics

1. 正常-模型、模型-治疗、模型-干预等比较应明确差异基因取反向交集还是同向交集。
2. 相关性分析前提是各组学样本来自同一个体，例如蛋白组 A1、代谢组 A1、微生物组 A1 对应同一只动物或同一患者。
3. 需评估最终代谢物、微生物或蛋白是否有实际价值；排查外源代谢物、污染菌或无解释意义的结果。

## 14. Single-Cell Analysis

1. 单细胞质控至少包含细胞数、基因数、线粒体占比三方面；阈值不强行统一，但需有文献或数据分布支持。
2. 细胞注释 marker 不能直接来源于 `FindAllMarkers` 得到的 top 特征基因；单一细胞类型尽量不要只用 1 个 marker。
3. 报告需补充细胞类型-marker 基因-cluster 列表，以及未注释前 cluster 的 marker 表达气泡图。
4. 至少应有一个关键基因在关键细胞中高表达并具有时序差异；若没有，需要反馈确认。
5. 单细胞关键细胞选择应尽量与转录组组织类型一致。例如转录组为肾小球组织时，单细胞关键细胞优先选择肾小球或相关细胞。
6. 若方案方向为特殊免疫细胞相关，免疫浸润需关注该免疫细胞是否差异，单细胞也应将对应免疫细胞作为关键细胞候选。
7. 单细胞受配体项目中复合蛋白需拆开。
8. 细胞通讯需明确是在疾病样本中还是所有样本中进行，也需明确是所有细胞类型间通讯还是关键细胞与其他细胞通讯。
9. 细胞通讯默认显著性阈值 `p < 0.05`；若受配体基因过少需扩大阈值，必须查找文献并申请确认。

## 15. Network Pharmacology and Direction Gene Expansion

1. 药物或疾病靶基因不能作为方向基因扩充来源。
2. 药靶和疾病靶点优先多数据库取交集；效果不好时可取并集并说明原因。
3. 网络药理学项目需尽量找全复方中所有药物；未找全必须与客户确认。
4. 药物别名应有参考依据，例如药典；存在中药不同来源或不同临床用途时需确认具体药材。
5. TCMSP、BATMAN 等数据库筛选阈值需在报告中描述。
6. 需保留网站下载的原始数据，整合文件包括药物-活性成分-靶基因列表。

## 16. Innovation and Biological Plausibility Review

所有项目均需要对关键结果做创新性和合理性评估：

1. 诊断项目：检查关键基因是否为 PCR/WB 等实验内参基因，是否已有大量疾病相关报道。
2. 预后项目：检查预后基因是否已有大量报道，且本项目 HR 方向是否与文献一致。
3. 数据库项目：检查暴露因素或临床模型指标是否过于通用或缺乏价值，例如年龄、性别、血压、激素等。
4. MR、临床模型和数据库结果需符合基本生物学和临床逻辑；不符合时需解释或调整。
5. 单基因项目需确认疾病和对照间有表达差异，趋势与主流文献一致，并思考是否存在 TF、甲基化、泛素化等特殊调控。

## 17. Special Dataset Rules

1. 急性髓系白血病：TCGA 常见取样部位为外周血，GEO 多为骨髓；因文献存在 TCGA 和 GEO 混用，可使用 GEO 骨髓数据集验证，但必须说明样本来源差异。
2. 同源数据集禁止在同一研究中分别用作训练集和验证集。已知示例：
   - 膜性肾病：GSE108113、GSE200828
   - 牙周炎：GSE16134、GSE10334
   - 溃疡性结肠炎：GSE87466、GSE92415
3. 肾母细胞瘤 TARGET-WT：UCSC 样本过少，不建议使用 UCSC 数据；可用 TCGAbiolinks 下载 GDC 数据。若无外部验证集，首选 7:3 验证，其次不做验证并说明。

## 18. Reporting Rules

1. 报告以 `templates/报告模板新2026.6.29.docx` 为唯一现行模板，并遵循 `references/report-template-map.md` 的页面、字体、分页、章节、着色、图表和引用规则。
2. 报告必须基于真实结果和方案要求编写，不能把模板或方案中的示例文字、示例数字和示例图当作真实结果。
3. 报告包含封面、自动目录、项目概述、分析结果、项目总结、项目调整、软件列表、固定 19 项报告质检、参考文献及模板自带的有效尾页。`1 项目概述` 从第 1 页开始编号。
4. 项目概述需覆盖背景、分析方法、数据来源、研究目标、关键科学问题、创新性和流程图；分析方法写明数据、分组、包/软件版本与引用、比较和阈值。
5. 分析结果只描述关键真实结果。数据集用蓝色加粗，阈值用绿色加粗，重点结果用红色加粗；每个结果小节末尾用深红加粗备注列出对应结果目录。
6. Word 报告只插入 PNG 图片；每张报告图在结果目录中同时保留 PNG 和 PDF。图片居中、清晰且大小适当，图注为黑色五号字并居中，不再添加浅蓝色独立图片名。
7. 项目总结围绕关键结果的生物学意义和机制解释展开，不罗列分析点；内容超过 2 页 A4，至少包含 5 篇关键基因相关参考文献，不要求绘制机理图。
8. “项目调整”记录所有数据集、模块、阈值、验证和结果处理变更；没有调整时写“无”。
9. “软件列表”必须来自实际脚本、manifest、R/Python 包、在线工具和数据库，并列出名称、版本或访问日期、用途和参考文献。
10. 软件列表和报告质检表使用三线表，五号黑字，中文宋体、西文 Times New Roman，单元格内容居中。
11. “参考文献”需覆盖方案文献、实际分析工具、数据库和特殊阈值依据，按 `[1]`、`[2]`、`[3]` 连续编号并保持格式一致。
12. 报告需覆盖方案要求的模块；缺失、跳过或调整的内容必须写入“项目调整”或相应说明。
13. 项目编号、疾病、物种、数据来源、分组、样本量和关键基因必须与方案或真实结果一致。
14. 特殊阈值、外部验证缺失、数据集替换、模型 AUC 等于 1 的处理、验证失败等风险必须在报告或项目调整中说明。
15. 报告提交审核前按 `references/report-qc-rules.md` 完成 19 项自检，并清除占位符、示例内容、批注、未处理修订和失效目录字段。

## 19. Review and Delivery Rules

1. 提交审核时应提供 Word 报告、服务器或 workspace 位置、项目绝对路径和必要说明。
2. 审核批注需一次性理解并处理；修改时不得删除未解决批注，应回复说明处理方式。
3. 若代码审核导致数据或结果调整，报告内容需同步更新并重新走报告审核。
4. 最终交付前检查脚本路径中是否含个人隐私信息；如需脱敏，应保证脱敏后仍可由用户修改路径复现。
5. 交付物至少包括：报告、可复现脚本、结果目录、关键 CSV 表格、PNG 图、必要 PDF 图、manual task 说明、PROJECT_MEMORY。

## 20. Skill Implementation Checklist

在每个项目中，Codex 执行该 skill 时至少检查以下内容：

1. `workflow/PROJECT_MEMORY.md` 是否记录项目基本信息、当前阶段、决策、风险、路径和下一步。
2. 每个分析点是否有 manifest 行，包含输入、输出、执行模式、状态、脚本路径、报告章节和备注。
3. 脚本是否符合目录模板、文件命名、CSV 输出、PNG 输出和可复现要求。
4. 差异、WGCNA、机器学习、预后、单细胞、网络、富集等模块是否满足本规范对应阈值。
5. 不满足阈值或需要特殊处理的地方是否标记为 `manual_required`、`blocked` 或写入 `notes`。
6. 长任务是否只做安全 smoke test，并在返回前清理临时测试数据和日志。
7. 报告输入是否只选择真实结果，且 Word 插图只使用 PNG。
8. 最终报告 QC 是否覆盖 `references/report-qc-rules.md` 和本文档第 18 节。
